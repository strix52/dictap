dictap 0.1.2 keeps failed recordings available for Retry ahead of ordinary Live recordings and removes false failure warnings from History.

- **Audio retention:** when retained audio exceeds 20 files or 200 MiB, dictap now trims recordings with usable text and no reported problem first. Failed recordings and partial results with warnings are trimmed afterward, oldest first. Active Retry recordings remain protected. The caps still apply, so failed audio is not kept indefinitely.
- **History:** ordinary Live transcripts no longer show an **Incomplete** tag or an amber "Live transcript not confirmed complete" message. Their status stays provisional, their audio stays available under the retention policy, and Retry remains available while that audio exists. Capture loss, timeouts and other errors still show warnings.
- Existing rows with only the exact old Live message receive the same display and retention treatment. Their stored records are not rewritten. Recordings already removed by earlier retention cannot be recovered by this update.

Download **dictap.exe** and run it to update. History, settings and your saved API key are preserved. No database migration, new dependency or setting is required; transcription timing and paste behavior are unchanged.

Validation: 183 automated tests passed, including file/byte retention caps, failed-only eviction, pinned audio and old History warnings. Formatting, Clippy and the Windows release build passed. Tests used temporary history and synthetic audio; microphone, provider and visual UI checks were not repeated for this patch.
