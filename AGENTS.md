# Project instructions

## Technical copy and releases

Use the `tech-copy` skill for all project copywriting: release notes, changelogs, README and documentation prose, product descriptions, and UI/error messages. Read its `SKILL.md` and required references before drafting or editing that copy, then follow its procedure and self-check.

On this machine, the skill is at `C:/Users/USER/.agents/skills/tech-copy/SKILL.md`; a second installation may be available under `C:/Users/USER/.codex/skills/tech-copy/SKILL.md`. Elsewhere, locate the installed skill by name. If it is unavailable, report that and obtain the skill before writing or publishing copy.

Before publishing a GitHub version, write its release notes through `tech-copy`, verify each claim against the actual changes and validation evidence, and state upgrade steps, compatibility changes, and material limitations. After publishing, verify the public release body and executable asset match the intended notes and build. Apply the same workflow when editing an existing release.

Use `writing-for-agents` when changing agent instruction files such as this one.
